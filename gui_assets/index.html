    What it does

    HotspotShade is a local relay for hotspot traffic. It opens each outbound socket on the physical hotspot interface. It sets IP_TTL=65 on that socket. The source device NAT subtracts 1, so the carrier sees 64. The source device also sends 64. A normal target device socket sends 64 and arrives as 63. That gap is the tethering signature. SOCKS5 mode does only this. Transparent tun mode adds utun capture and route changes, so apps need no proxy settings.

    The TTL step

    One setting on each outbound socket.

    65relay
    →
    −1The source device NAT
    →
    64carrier

    The relay sets IP_TTL with setsockopt on macOS. Windows uses the same per-socket option. No kernel extension. No packet rewriting. Direct mode needs no app on the source device. Source device proxy mode uses the optional source device app.

    Threat model

    What this hides and what it does not.

    • Hides: the one-hop TTL gap between tethered traffic and source device traffic.
    • Does not hide: TLS fingerprints, SNI, HTTP user agents, TCP options, DNS patterns, timing, or destination choice.
    • Trust: the relay does not decrypt TLS. It opens outbound sockets as you.
    • Scope: works at the socket layer. Apps that bypass it, and traffic from other devices, are not covered.

    Platform notes

    Same idea, different capture layers.

    macOS

    Transparent mode creates a utun and installs two /1 routes. Root is needed for utun creation and route changes. A clean stop removes the routes.

    Windows

    Transparent mode uses a wintun adapter and Win32 routing. It needs an elevated process. SOCKS5 mode needs no elevation. Per-socket TTL behavior can differ from macOS.
